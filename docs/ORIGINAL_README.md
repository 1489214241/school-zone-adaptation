# 小区—学校归属补全（学区划片）

从教育局公布的招生政策文字出发，先用规则判出能判的小区，其余小区用参照检索网络补全，回答"每个小区归哪所公办小学"。
数据：长沙四区（天心、芙蓉、雨花、开福）、杭州四区（拱墅、萧山、富阳、临安），2026 年。

## 目录

```
学区归属模型_代码库/
├── configs/
│   ├── default.json            整理版（推荐）
│   └── final_20261103.json     两城最终版（11-03 定版）的设置，用于复现和对照
├── data/                       由 scripts/export_data.py 导出的八个区数据，不手改
├── zoning/                     方法本身，按六步分文件
│   ├── data.py                 读数据
│   ├── rules.py                第一、二步：政策文字 → 判入 / 排除 / 不知道（五条原则）
│   ├── evidence.py             第三步：模型的两类输入（参照一路、学校一路，按"块"组织）
│   ├── model.py                第四步：参照检索网络
│   ├── train.py                第五步：训练题、权重、线性起点、训练循环
│   ├── predict.py              第六步：输出每个小区的答案
│   ├── evaluate.py             计分与空间块重抽区间
│   ├── references.py           每校额外核验 K 个参照（设置里写 references 才用）
│   ├── baselines.py            主表的对照方法
│   └── correction.py           可选（默认不用）：冻结模型后只在带名字证据处修正
├── third_party/TALENT/         ModernNCA 官方核心代码（MIT，原样复制）
├── scripts/
│   ├── run.py                  一个入口跑完全流程
│   ├── run_baselines.py        对照方法（与 run.py 同一份设置）
│   ├── main_table.py           主表与台阶表
│   ├── ablation_table.py       从完整模型逐个去掉一处改动
│   ├── correct.py              可选：限定范围的证据修正（configs/name_correction.json）
│   ├── verify.py               与项目旧程序逐位核对
│   └── export_data.py          一次性：从项目旧程序导出 data/

```

只有 `scripts/export_data.py` 和 `scripts/verify.py` 引用项目里的旧代码；`zoning/` 只读 `data/`。

## 方法

```
政策文字的原子观察（名单命中、四至每条边判在哪侧、行政范围、"不含"）
   │  rules.py：五条原则
   │    一 条款要各边同时满足      二 明写的例外优先      三 拿不准就不判
   │    四 学校范围是各条款的"或"，四至完整时范围外记排除   五 名单点名 → 四至恰好一所 → 冲突不判 → 其余交给模型
   ├──────────► 规则判出的小区：直接输出（长沙 1437 个，判错 44 个）
   ▼
evidence.py：每个待判小区，每个候选一行证据
   参照一路（小区 × 附近已知小区）：距离方向、四至状态及与参照是否一致、跨路、学出的分界、同社区
   学校一路（小区 × 学校）：到校址的距离方向、四至状态与排除、名字是否对上、所在社区被整社区点名
   ▼
model.py：每个候选一个分 ＝ 线性项 ＋ 小网络（32→16→1）；所有候选一起 softmax，按学校加总
   ▲
train.py：训练题 ＝ 本区规则已知 ＋ 其余七区规则已知 ＋ 其余七区规则没判出、有官方答案的小区
          每个楼盘组等权；线性项起点先用本区规则已知拟合；40 步；10 个种子
   ▼
predict.py：规则判出的照原判，其余取 10 个种子概率平均后最高的学校
```

```

D:/ana/python.exe -X utf8 scripts/run.py configs/a_platform_list_input_20261106.json   # 11-06 整理版（杭州把平台小区名单也当输入）
```

### 长沙多校集合（11-09）

长沙政策重复点名的学校集合完整保留，不把重复点名解释成已确认的家庭任选权。`policy_input/<区>.json` 从政策观察和 `observations/verified_multischool.json` 导出逐小区标记、学校、原文、实体证据和未决项，不读取 Gold。新增核验通过的江河双水湾、三0一佳园、香樟路电信宿舍、中航长沙设计研究院宿舍，输出直接使用政策学校集合，不依赖模型第一名。核验文件绑定政策观察哈希、小区编号和名称、学校名称及原条款；不匹配时拒绝应用，不按学校对传播。未决关系不参与输出。

这项修改只作用于最终输出，`rules.known`、参照、训练、概率及 Gold 保持原样。CSV 保留“多校依据”“任选资格”，并增加“适用范围”“政策年份”。杭州不进入这条修正路径。

`run.py` 的 `changsha_sets` 读取最终预测，以学校集合完全相等为长沙主评估，同时报告学校级微平均查准/查全、逐学校指标、单校/多校分组以及完整例外表。非法学校编号（当前天心有5条 `-1`）单列。原 `summary`、`overall` 仍是未应用逐小区核验覆盖的历史模型/规则口径，`metric_notes` 明示区别；比较修正收益须使用最终输出重放脚本，不能混用旧指标。

不重训、仅重放当前长沙输出：

```
D:/ana/python.exe -X utf8 scripts/replay_changsha_sets.py
D:/ana/python.exe -X utf8 -m unittest discover -s tests -p test_changsha_sets.py
```

重放读取 `outputs/hz_comm_ER` 冻结概率，写入独立目录 `outputs/changsha_verified_sets_20261109/`，逐条检查变化仅来自核验输入、原始观察/Gold/概率/原输出哈希未变，并核对杭州四区全部输出字段未变。旧注释版输出 `outputs/changsha_multischool_20261109/` 留作修改前记录。

本轮实测：长沙有效 Gold 3858 条，完整集合正确 3358→3362（87.0399%→87.1436%）；13 条双校 Gold 完整判对 5→9；改对4、改坏0，单校 Gold 不变。输入多校标记9→13，其中4条原有标记的Gold为单校，故“13条多校输出”并不意味着13条双校Gold全对。世茂璀璨天城、凤凰台、江河中央洋房、中国轻总会长沙设计院仍待核。候选来自同批错误审计，证据包含人工实体判定和二手来源，属于开发集输入/输出修正收益，不是模型能力提升或独立验证。

来源生成器 `scripts/build_changsha_verified_sets.py` 只读官方CSV和政策观察，不导入数据加载器、不读Gold；政策原文变化时拒绝再生成。逐条来源与未决原因见工作区 `科研推进/长沙多校关系补全_20261109/source_review.json` 和 `完成说明.txt`。集合输出用于当前地图归属任务，不作为家庭任选或最终入学资格的判定。

### 每校额外核验参照、对照方法、主表（11-09）

问题设定：跨区少样本分类（区＝任务、学校＝新类别；支持集＝规则判出的小区＋每校额外核验 K 个；其余为查询集）。见 `科研推进/问题定义与参照数_20261109.md`。

| 入口 | 做什么 |
|---|---|
| 设置 `references: {"k": K, "seed": s}` | 每校从官方答案里随机挑 K 个楼盘当核验参照（模拟核实；`zoning/references.py`），并入已知小区，同时当参照和训练题，挑中的不再评价。不设就与原来逐位相同 |
| `scripts/run_baselines.py <设置>` | 同一批规则结果、同一批核验参照、同一批评价小区上跑对照（`zoning/baselines.py`）：最近学校、抄最近、标签传播（支持集留出选 α）、ProtoNet、ModernNCA 官方核心（`third_party/TALENT`，原样调用）；后两种每区单独训练，raw＝原版，policy＝加政策排除 |
| `scripts/main_table.py <设置> --tag <名>` | 主表：K∈{0,1,3,5}，K>0 换 3 批核验对象；台阶表（K=0、1）：ModernNCA 原版 → ①成对证据 → ②学校当候选 → ③政策证据 → ④别区答案训练（完整模型）。输出 `outputs/main_<名>/summary.md` |
| 设置 `model.paths: ["pair"]`、`evidence.exclusion_to_model: "none"` | 台阶表用的消融开关：去掉学校一路；排除不交给模型 |
| `scripts/ablation_table.py <设置> --tag <名>` | 从完整模型逐个去掉①②③④（K=0 一批、K=1 三批），沿用 main_table 的完整模型与评价集；输出 `outputs/main_<名>/ablation.md`。去掉跨路块时跨路份额按 0 算（`evidence.Inputs.crossing_cols`） |

`scripts/verify.py train` 在加入这些之后仍逐位一致（芙蓉 20261131，概率最大差 0）。

pre_v1 结果（11-09/10，现行数据，杭州答案未冻结）：模型部分准确率 77.13/81.11/84.18/86.43（K=0/1/3/5），每档每批都赢全部对照（区间不含 0）。从完整模型逐个去掉（事先判定 `outputs/main_pre_v1/ablation_plan.md`）：K=0 四处都有用；K=1 ①③④有用（三批下界都 >0），②学校当候选三批都跨零（−0.68/−0.35/+0.08）——它管的是"本校没有参照"，K≥1 后不再起作用。台阶表里 K=1 ③跨零是加的顺序造成的。

### 杭州名单点名的两个来源（11-07，改口径的依据）

杭州规则的名单点名，除范围文字外，还用了入学平台每校页面上的小区名单（每行一个小区；1305 个点名正例里 1190 个来自它）。长沙的点名写在政策文字本身里（如"……合围区域（包括……元盛大厦……）"），杭州的政策文字（范围描述）本身几乎不点楼盘名。有地图答案的小区里，只靠政策文字本身点名判出的：长沙 天心 29%、芙蓉 29%、雨花 27%、开福 16%；杭州 拱墅 0%、萧山 8%、富阳 0%、临安 0%（加上平台名单后 21–33%）。所以 11-06 整理版里杭州多用了一类长沙没有的资料（与地图同一条平台记录的查询名单）；按"输入＝政策文字"的定义，下面的"地图＋名单"口径更一致。
`configs/ablation_hz_text_names.json`（`rules.hangzhou_names = policy_text`）只用范围文字，相当于只去掉杭州的大部分点名（长沙的点名还在），整体正确率（5630 个有答案小区）：

| | 范围文字＋平台名单（11-06 整理版） | 只用范围文字 | 差 |
|---|---|---|---|
| 两城 | 88.21% | 81.69% | −6.52 [−8.93, −4.54] |
| 长沙 | 87.89% | 87.26% | −0.62 [−1.03, −0.21] |
| 杭州 | 88.91% | 69.50% | −19.41 [−25.47, −13.84] |

另一种口径 `configs/hz_map_list_gold.json`（`data.hangzhou_gold = map_list`）：没有可用地图的学校，用这张名单当官方答案（`scripts/export_list_gold.py`，505 个），名单因此不再当输入。整体：长沙 87.42%、杭州地图答案 69.61%、杭州名单答案 75.05%（双学区选中任一所算对；严格 62.77%）、两城 81.27%（6135 个）。详见 `科研推进/杭州名单补答案_20261107/结论.md`。
`eval.json` 现在同时给模型部分（summary）和整体（overall，规则判出的按规则答案）；`python scripts/run.py <设置> --eval-only` 用已有概率重新评价。

## 限制

- 都是开发评价：这些官方答案以前被很多实验看过。
- 杭州的输出只覆盖有官方答案或规则判出的小区（与两城最终版的训练评价点集相同）。
- 社区、名字两类证据由旧程序算好后导出（data/<区>/extra_evidence.npz），代码里不重算。
